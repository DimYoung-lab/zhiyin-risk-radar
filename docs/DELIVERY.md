# 第一题交付说明

作品：**知因雷达——可配置投资监控与风险雷达**。产品版本：**v0.1.0**。

代码、说明与现有验证材料由Codex整理；新版演示视频由用户按[产品演示操作顺序](RECORDING_GUIDE.md)录制。待提交目录初次生成时不含旧视频，新视频加入前不属于完整最终提交物。具体状态见目录根部的提交说明与`delivery-manifest.json`。

- 在线产品：[打开知因雷达](https://zhiyin-risk-radar.dimyoung-0719.workers.dev)
- 源码仓库：[DimYoung-lab/zhiyin-risk-radar](https://github.com/DimYoung-lab/zhiyin-risk-radar)
- 提交视频：目录根部的`演示视频.mp4`，必须60–180秒。旧168秒视频仅保留为本地参考，不自动加入新材料。
- 最终上传：包含全部材料与新视频的一个ZIP，小于30MB；压缩包不要嵌套另一个源码ZIP。

## 建议体验顺序

先看视频，再打开在线产品。点击「新建演示」即可检查提醒、去重、数据异常、恢复和冷却；这些是明确标注的构造数据，使用相同的规则引擎和持久化流程。演示结束后可在详情中删除，确认后释放任务额度并清理关联记录。

体验真实链路时，点击「新建任务」，输入「贵州茅台跌幅达到3%，并进入热榜前10时提醒我，冷却24小时」。核对草稿，预检真实数据，再确认启用。真实任务在网页关闭后继续由服务器调度，提醒保存在应用内。评审后可以暂停自己创建的真实任务。

市场休市或数据跨日时，真实任务可能显示未到检查时间或数据不可用；页面会给出原因。异常没有被替换成构造行情。演示场景可以在休市期间完整体验主链路。

## 新视频与提交前核对

新成片应展示自然语言草稿、修改与预检、确认启用、计划与状态，以及隔离演示中的去重、异常、恢复、冷却、版本与提醒追溯。具体点击顺序见[RECORDING_GUIDE.md](RECORDING_GUIDE.md)。金融数值按当次画面说明，构造场景必须保留演示标签；不声称录制期间未实际发生的真实提醒或Cron执行。

Codex已准备源码、说明、实际报告与截图。用户录完将文件位置告知Codex，即可读取视频元数据、加入提交目录并更新SHA-256。可自行压缩最终目录，也可使用整理脚本的`--zip`选项。用户仍需观看成片确认文字可读与主链路操作完整，机器检测时长不能替代内容核对。

```bash
npm run package:submission
npm run package:submission -- --video /绝对路径/新版演示视频.mp4
npm run check:docs -- submission/待提交_知因雷达_v0.1.0
# 自动生成最终ZIP时，在第二条命令末尾追加 --zip
```

整理脚本从已提交Git版本生成材料，校验源码/报告引用、文件哈希与凭证排除。没有新视频时清单明确标记`readyForSubmission: false`，并只提供材料目录和独立源码ZIP。新视频加入后记录真实时长、尺寸、编码、音轨和哈希；不会复制旧视频的字幕声明或剪辑记录。最终ZIP以小于30,000,000字节为检查上限，兼容平台“30MB以内”的限制。

## 实际验证与范围

**47 / 47项自动测试、33 / 33项线上API检查通过**；本地实际Worker此前同样33项通过，TypeScript与生产构建通过。真实Cron在客户端进程退出后完成检查，两次记录分别保存在`verification/cron-proof.json`与`verification/cron-latest-proof.json`。浏览器核验了桌面和手机布局、真实创建流程和演示流程。各报告保留实际执行时间及对应部署版本，没有因重新整理材料而冒称重新执行。

`verification/integration-first-retrace.json`保留一次26 / 27的失败结果：模型给盘中计划返回了不参与执行的`at=null`。修正只规范化该模式无关字段，没有猜测有效时间、频率或阈值。随后新增回归测试并完成真实API验证，最终结果见`verification/integration-report.json`。

计划逐项验收与独立产品裁判意见见[AUDIT.md](AUDIT.md)，评分摘录见`verification/product-audit-report.json`。92 / 100为内部产品评审，不是同花顺官方考试成绩。

用户视角评审补齐未保存编辑保护、旧预检失效、取消后的迟到解析与手机保存错误反馈，四项均已部署并通过线上复核。步骤、截图及未采纳的可选需求见[UX_REVIEW.md](UX_REVIEW.md)，机器证据见`verification/ux-review-report.json`。该轮仅改前端，API与Cron报告保留原后端验证时间。

模型采用非思考模式、`reasoning_effort: none`、1800 tokens、温度0.1和35秒超时，已补充输出截断保护。两模式各6项真实调用对比和最终配置6项复核均通过，报告为`verification/model-config-comparison.json`与`verification/model-config-selected.json`；依据和样本局限见[AI_USAGE.md](AI_USAGE.md)。模型配置部署后于13:08:55通过33项线上API检查，报告记录其部署版本。

后续下拉箭头、单位间距、收盘频率与窄屏文字修正，以及模型版本/调用别名与3个运行名额说明，本地和线上各8项浏览器检查通过。证据见`verification/ui-detail-review.json`与[UX_REVIEW.md](UX_REVIEW.md)，最新部署版本见交付清单；后端报告保留此前执行时间。

当前覆盖A股单证券价格、涨跌幅、热榜与日历组合。公告事件、多证券联动、邮件 / 推送、登录同步与长期稳定性验证尚未完成，完整边界见[README](../README.md)。产品提供条件监控与研究信息，不提供交易或仓位建议。

## 包内目录

- `00_提交说明.md`：评审入口、链接、源码版本与视频状态。
- `README.md`：产品、运行和部署说明。
- `src/`、`migrations/`、`tests/`、`scripts/`及配置：可复现源码。
- `docs/`：计划、设计、测试与AI使用记录，含界面截图及录制操作顺序。
- `演示视频.mp4`：用户的新实际操作录屏，60–180秒；待录制目录尚不包含此文件。
- `verification/`：自动测试、线上API、真实调度、模型验证与失败记录。
- `delivery-manifest.json`：源码Git版本、各项验证原执行时间和部署版本、视频状态 / 元数据与文件SHA-256。清单不计算自身哈希，避免自引用。

包内不含运行密钥、Cookie、浏览器资料、`node_modules`或原始题目附件。按README配置自己的凭证即可部署；没有凭证也能运行隔离演示与自动测试。

独立源码ZIP与旧录屏存放在待提交目录之外。最终上传整个待提交目录的ZIP，保留其中的`verification/`报告与截图；只有源码ZIP不足以满足题目第四项要求。
