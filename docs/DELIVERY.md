## 建议体验顺序

先看视频，再打开在线产品。点击「新建演示」即可检查提醒、去重、数据异常、恢复和冷却；这些是明确标注的构造数据，使用相同的规则引擎和持久化流程。演示结束后可在详情中删除，确认后释放任务额度并清理关联记录。

体验真实链路时，点击「新建任务」，输入「贵州茅台跌幅达到3%，并进入热榜前10时提醒我，冷却24小时」。核对草稿，预检真实数据，再确认启用。真实任务在网页关闭后继续由服务器调度，提醒保存在应用内。评审后可以暂停自己创建的真实任务。

市场休市或数据跨日时，真实任务可能显示未到检查时间或数据不可用；页面会给出原因。异常没有被替换成构造行情。演示场景可以在休市期间完整体验主链路。

最终目录包括视频、源码、说明、实际报告和截图。整理脚本更新视频元数据与SHA-256，并用`--zip`生成最终ZIP、检查完整性和30MB限制。以下命令用于再次整理；请保留原片，并显式提供视频路径。

```bash
npm run package:submission -- --video submission/待提交_知因雷达_v0.1.0/演示视频.mp4 --zip
npm run check:docs -- submission/待提交_知因雷达_v0.1.0
```

整理脚本从已提交Git版本生成材料，校验源码/报告引用、文件哈希与凭证排除。没有新视频时清单明确标记`readyForSubmission: false`，并只提供材料目录。新视频加入后记录真实时长、尺寸、编码、音轨和哈希；不会复制旧视频的字幕声明或剪辑记录。视频位于待提交目录内时，会先复制成片再更新目录，保留原文件内容。最终ZIP命名为`知因雷达_v0.1.0_完整提交.zip`，以小于30,000,000字节为检查上限，兼容平台“30MB以内”的限制。

## 实际验证与范围

**47 / 47项自动测试、33 / 33项线上API检查通过**；本地实际Worker此前同样33项通过，TypeScript与生产构建通过。真实Cron在客户端进程退出后完成检查，两次记录分别保存在`verification/cron-proof.json`与`verification/cron-latest-proof.json`。浏览器核验了桌面和手机布局、真实创建流程和演示流程。各报告保留实际执行时间及对应部署版本，没有因重新整理材料而冒称重新执行。

`verification/integration-first-retrace.json`保留一次26 / 27的失败结果：模型给盘中计划返回了不参与执行的`at=null`。修正只规范化该模式无关字段，没有猜测有效时间、频率或阈值。随后新增回归测试并完成真实API验证，最终结果见`verification/integration-report.json`。

计划逐项验收与独立产品裁判意见见[AUDIT.md](AUDIT.md)，评分摘录见`verification/product-audit-report.json`。92 / 100为内部产品评审，不是同花顺官方考试成绩。

用户视角评审补齐未保存编辑保护、旧预检失效、取消后的迟到解析与手机保存错误反馈，四项均已部署并通过线上复核。步骤、截图及未采纳的可选需求见[UX_REVIEW.md](UX_REVIEW.md)，机器证据见`verification/ux-review-report.json`。该轮仅改前端，API与Cron报告保留原后端验证时间。

模型采用非思考模式、`reasoning_effort: none`、1800 tokens、温度0.1和35秒超时，已补充输出截断保护。两模式各6项真实调用对比和最终配置6项复核均通过，报告为`verification/model-config-comparison.json`与`verification/model-config-selected.json`；依据和样本局限见[AI_USAGE.md](AI_USAGE.md)。模型配置部署后于13:08:55通过33项线上API检查，报告记录其部署版本。

后续下拉箭头、单位间距、收盘频率与窄屏文字修正，以及模型版本/调用别名与3个运行名额说明，本地和线上各8项浏览器检查通过。证据见`verification/ui-detail-review.json`与[UX_REVIEW.md](UX_REVIEW.md)，最新部署版本见交付清单；后端报告保留此前执行时间。
