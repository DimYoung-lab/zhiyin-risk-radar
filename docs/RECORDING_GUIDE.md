# 知因雷达：笔试演示操作顺序

产品版本v0.1.0。任务界面的v1、v2是各任务的规则修订版本。题目要求成片60–180秒，建议目标170秒；以下时间是成片节奏，原录屏可更长，再剪除加载和多余停顿。

## 录制前准备

1. 打开 [知因雷达](https://zhiyin-risk-radar.dimyoung-0719.workers.dev)，使用同一个浏览器空间完成整段操作。
2. 将自己不再需要的真实任务暂停或删除，留出一个运行额度；演示任务也可删除后重新创建。仅操作自己创建的任务。
3. 把下方自然语言示例预先复制好，先完整练习一遍。练习后暂停真实任务，删除演示任务，正式录制重新创建演示，以免已有提醒和冷却影响结果。
4. 若真实接口在录制时不可用，保留并说明实际原因；真实数据和隔离演示分别有明确标签。无需等当天行情恰好满足条件。

输入示例：

> 贵州茅台跌幅达到3%，并进入热榜前10时提醒我，每5分钟检查一次，冷却24小时。

## 操作时核对的细节

- “跌幅达到3%”要核对为**涨跌幅不超过-3%**，不能写成大于正3%。如果模型草稿需要澄清或未通过校验，先按界面补充明确输入，再重新生成；不把未成功的调用讲成成功。
- 实际操作的次序是先修改规则、再预检。预检后继续改规则会清除旧结果，需要重新预检。
- 热榜只支持前30，榜外证券显示未进入前30或无法确定具体排名；不声称排在第31。真实数值以录制当次画面为准。
- 点击验证场景后等状态更新，再点下一项。说明文字在详情下方，需要时慢慢滚动到检查原因和证据。
- 演示阈值改为前8名仍能覆盖固定的第5名构造值；不要改成前1名后期待“条件满足”按钮强行造出满足结果。
- 新一轮·冷却中会构造先不满足、再满足的过程；无需另外等24小时。演示使用相同引擎与持久化，但不参加真实Cron调度。
- 从提醒中心选取该演示任务的v1提醒，再展示“该提醒对应的检查·v1”和完整检查ID。即使当前任务已是v2，原证据仍对应v1。
- 后台持续运行的证明见 [TESTING.md](TESTING.md) 的真实Cron记录，视频展示计划、状态与解释。新建的录制任务不必在3分钟内等待一个实际调度周期。

## 完成后的材料

录完确认：成片60–180秒，文字和原因可读，真实取数与演示标签清楚；录制用真实任务已暂停或删除。源码、README、AI使用记录与测试说明继续随提交包交付，详见 [DELIVERY.md](DELIVERY.md)。

新版录屏由你完成。建议把新成片保存为`submission/新版演示视频.mp4`，保留原始录屏；把文件位置告知Codex即可继续核验、放入待提交目录并更新文件清单。旧168秒录屏仅保留作参考，不会自动混入新提交材料。

也可在项目环境内运行`npm run package:submission -- --video /绝对路径/新版演示视频.mp4`。整理命令会读取真实时长、尺寸、编码和音轨，要求成片60–180秒，并将其复制为待提交目录根部的`演示视频.mp4`；不会宣称未核验的字幕或操作内容已经通过。视频的可读性、真实/演示标签及操作覆盖仍需观看确认。最后压缩整个待提交目录，单个ZIP小于30MB；`--zip`可代为生成并核验ZIP。

待提交目录里的所有文件（包括源码和验证报告）都应保留；独立源码ZIP供备份，不必再次塞进最终提交目录。不要上传只有源码、没有视频与验证材料的源码ZIP。
