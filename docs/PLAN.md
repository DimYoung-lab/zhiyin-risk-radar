# 第一题执行计划

## 目标与时间

考试提交期限为平台的 24 小时倒计时。用户可参与约 4–5 小时；开发、调试、测试、文档与录屏由 Codex 完成。按题目验收项推进，不设 2–3 小时的内部交付限制，不为赶初版删减必须能力。用户仅需配合登录、体验与最终核对。

## 必须完成

- 文字意图→规则草稿→编辑与确认→真实数据→自动检查→提醒与证据。
- 价格、涨跌幅、热榜、指定日期、交易日和 AND/OR 组合。
- 后台调度、暂停恢复、版本、幂等、去重、冷却、故障退避和恢复。
- 数据缺失、冲突、过期有明确解释；数字回到原字段、单位、来源、时点。
- Web URL、源码仓库、README、60–180 秒产品录屏、AI 使用/验证记录和测试说明，压缩包小于 30 MB。

## 技术选择

React / TypeScript / Vite / Hono；Cloudflare Workers 静态资源与 API；D1 状态持久化；每分钟 Cron 检查到期任务。DeepSeek Flash 仅解析文本，不使用多模态。扶摇 REST 提供证券消歧、行情、热榜和截至当日的交易日历。

## 验收

先通过真实模型和数据取数，再验证创建/编辑/启用链路；使用隔离构造场景验证重复触发、冷却、数据异常、恢复和版本变化；通过离开网页后的调度记录验证后台运行。最终提交前检查 URL、仓库、录屏、包大小与密钥泄露。

## 5. 实施顺序与所需配合（调整版）

时间均为参考估算，不作为删减需求或压缩验证的硬性限制。按验收项完成程度推进，以考试平台的实际提交截止时间为边界。用户无需全程在线。

| 阶段 | Codex 工作安排 | 用户预计参与 | 完成标志 |
|---|---|---|---|
| Git、密钥、账号与接口验证 | 优先完成，当前已建立仓库并验证 Cloudflare 和扶摇 | 约 5–10 分钟，已基本完成 | 数据与部署条件成立 |
| 规则、持久化、调度和界面 | 参考 2–4 小时，依质量调整 | 无需参与 | 完整主链路可运行 |
| 异常、恢复、并发与测试 | 参考 1–2 小时，发现问题即修复 | 初版体验约 15–20 分钟 | 必须场景通过 |
| 上线及后台运行核验 | 参考 30–60 分钟 | 通常无需参与 | URL 可操作，关闭网页仍运行 |
| 文档、视频与提交包 | 参考 30–60 分钟 | 最终核对约 20–30 分钟 | 交付齐全且小于 30 MB |
| 排错与提交缓冲 | 使用平台剩余时间，优先修复阻断项 | 仅需要账号或明确缺失信息时联系 | 链接、包与提交信息复核 |

用户参与合计约 40–60 分钟，出现外部账号问题时可能增加；并非要求连续投入 23 小时或全程参与调试。DeepSeek Flash 仅处理文字；质量优先，不设 2–3 小时初版限制。
