# AI 使用与验证记录

## 开发过程

用户提供题目截图和原附件，选择第一题，要求严格按题目完成可运行作品、版本管理和全部交付物。用户授权 Codex 辅助产品设计、全栈实现、金融接口选择、测试、部署与材料整理；方案、界面、服务和测试代码主要由 Codex 生成并执行验证。本文明确披露 AI 参与，不声称这些工作完全由候选人独立手写。

用户确认运行时使用 DeepSeek Flash 的文字能力，并指出不宜使用其多模态。开发中读过题目全文、接口文档和实际响应，再把范围限定为单证券价格、热榜、日历及组合；未使用模型猜测行情。用户反馈初版界面“AI 味重”后，使用 frontend-design 与 UI UX Pro Max 重新组织任务表和详情，去掉装饰性标语与光效，复核移动布局和实际操作。

| 阶段 | 交给 AI 的问题 | 产物与检查 |
|---|---|---|
| 题目与计划 | 比较三题，并在第一题要求内选择可完成的主链路 | `PLAN.md`；逐项对应要求，平台 24 小时倒计时优先于附件的 48 小时文字 |
| 实现 | 如何把自然语言转换成可修改规则，并保持长期执行状态 | 统一 Schema、确定性引擎、Worker / D1 / Cron；规则、并发、异常和真实 API 验证 |
| 界面迭代 | 投资工作台如何减少模板化视觉、便于反复检查 | 当前中文任务表、详情栏和移动布局；截图与浏览器操作核验 |
| 交付 | 如何说明实际完成范围和验证证据 | README、设计与测试说明、运行报告、实际操作录屏 |

## 运行时模型

后端调用 DeepSeek 原生 `/chat/completions`，模型参数 `deepseek-flash`，JSON 输出、低温度、关闭 thinking。系统提示限定可用字段、单位、阈值、未支持事项与澄清要求；提示文本位于 `src/server/providers.ts`。模型的证券名称 / 代码查询由真实检索确认，草稿经过 Schema 校验，最后由用户确认启用。

模型不执行监控、不自动选择买卖、不提供仓位或涨跌预测。启用后只调用金融接口与确定性规则引擎；模型不可用时可手动配置，已有任务不受模型故障影响。

线上真实调用已核验：组合条件得到 `≤ -3%` 与 `≤ 10 名`；模糊“大跌”返回澄清；回购公告返回不支持。审计保存模型名、输入 SHA-256 哈希、验证状态、服务返回 token 用量和时间，当前空间可查询 `/api/ai-audit`。提交包 `verification/ai-verification.json` 是实际 D1 记录摘录，不包含密钥或完整对话。失败在返回前发生时尚未建立完整失败审计，这属于未做事项。

## 实际发现、修正与复核

| 问题 | 修正 | 复核 |
|---|---|---|
| 初期考虑了“前50”热榜示例，但接口仅返回前30 | 收紧规则阈值，榜外只说明未进入前30；不编造名次 | Schema、完整 / 不完整榜单、真实预检 |
| 交易日历只覆盖至当日 | 未来日期仅给计划；盘中 / 收盘执行时确认当天交易日 | 日历适配器、上海时区和调度测试 |
| 客户端模型别名不一定可作为服务端 API 模型名 | 核对实际模型接口，使用 `deepseek-flash` | 真实调用与审计记录 |
| 用 `snapshot` 子串判断接口类别，误把行情标成热榜 | 使用明确路径判断证据类型 | 浏览器行情 / 热榜标签与原字段 |
| 开发服务重启时返回非JSON503，出现底层解析报错 | 客户端识别网关 / 网络错误，提示重试 | 3 项客户端错误处理测试 |
| 初读持续状态与取得租约之间可能有其他检查提交 | 取得租约后重读最新状态，提交使用版本与令牌校验 | D1 并发集成测试与去重断言 |
| 跳过检查可能清除既有失败状态 | 跳过保持健康状态与失败计数，不假装恢复 | 跳过路径检查与后续恢复流程 |
| 运行完成时间曾复用开始时间，早于实际采集 | 实际运行以采集后时钟记录完成；演示保留明确场景时钟 | 集成断言与重新执行真实 Cron，23:35:14.889 完成晚于所有采集 |
| 用户认为视觉模板化 | 改为任务表与检查详情，中文实用文案、克制色彩和清晰层级 | 新版构建、真实创建流程和390px无横向溢出 |

验证详细结果与局限见 `TESTING.md`。不将模型输出直接视为真相，也不把通过有限测试写成长期运行保证。
